# DokuWiki 19.0 testing

## Scope and package decision

Debian 13 Trixie provides DokuWiki 2024-02-06b+dfsg-9, so DokuWiki 19.0 uses
that package instead of downloading an upstream archive. DokuWiki, PHP 8.4,
Apache and all required PHP modules therefore share Debian's signed APT update
path.

The package keeps application code in `/usr/share/dokuwiki`, configuration in
`/etc/dokuwiki`, and writable wiki state in `/var/lib/dokuwiki`. The appliance
preserves the firstboot administrator, clean URLs, public creation policy,
authenticated upload policy and TurnKey start page on that layout.

## Static and disposable checks

```sh
bash -n conf.d/main tests/v19.sh \
  overlay/usr/lib/inithooks/firstboot.d/40dokuwiki
python3 -m py_compile overlay/usr/lib/inithooks/bin/dokuwiki.py
git diff --check
```

A disposable Debian Trixie container installed the exact DokuWiki package,
applied the appliance configuration, started Apache, loaded both `/` and
`/start`, authenticated as the seeded administrator, and completed a real web
edit and plain-text persistence round trip.

## Known limitation

Docker runtime validation does not exercise the installer, appliance kernel,
bootloader or physical hardware. DokuWiki adds no appliance-specific behavior
at those boundaries, so the validated Core 19 baseline supplies inherited
evidence.

## Deferred issues

- The primary flow proves administrator editing and the ACL values that grant
  ordinary authenticated users upload permission. It does not create a second
  user or upload a large media file.
- DokuWiki farms, non-default templates, external authentication backends and
  outbound mail delivery require optional configuration and are outside the
  appliance's initial workflow.
